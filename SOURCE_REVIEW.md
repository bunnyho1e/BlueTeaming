# Source screening and evidence

**Review date: 2026-10-21. Active projects: 410.**

[Full evidence](source-review.json) · [Held candidates](EXCLUDED.md) · [Security policy](SECURITY.md)

## Method and boundaries

1. Resolve the canonical GitHub or GitLab project, record provider metadata, deduplicate aliases and prefer original upstreams over forks.
2. Hold archived or disabled projects and sources without provider-reported activity in the previous three years. Activity and popularity are quality signals, not security attestations.
3. Resolve a complete 40-character commit and retain its provider date. Provider-reported signature status is recorded when available; this workflow does not independently verify maintainer signing keys.
4. Query OSV for the exact commit. A matching advisory places that candidate on hold. No match can mean no indexed record; it does not establish the absence of vulnerabilities.
5. Read a bounded source snapshot or selected pinned files without extracting or executing upstream code. Fingerprint inspected bytes with SHA-256. Selected GitHub files are checked against tree blob hashes where available.
6. Examine indicators for remote installer pipelines, encoded execution, credential-store references, webhooks, miners, persistence and changes to security controls. Retain contextual interpretations and appropriate usage classes.

The snapshot path limits compressed input to 24 MiB, expanded regular-file bytes to 128 MiB, individual files to 1 MiB and archive members to 90,000. It scans selected common source/config/rule suffixes and build manifests. Non-text files, large files, symlinks and unselected suffixes are omitted. Source archives may apply upstream export attributes. A snapshot fingerprint records retrieved bytes, not a signed publisher attestation.

Large source trees and bounded-download failures use selected-file inspection. A selected-file screen requires at least three inspected text files, including a source/config/build file. A complete bounded snapshot of a small project can pass with two text files when one contains source or configuration. These are minimum evidence gates, not comprehensive assurance. Limits and errors remain attached to each record. The private working set retains selected source text; the published evidence contains its paths, hashes and representative indicator excerpts.

Where direct GitLab source downloads were unavailable, matching commit objects in the upstream GitHub mirrors were used for Wireshark, AppArmor and GnuTLS. Their canonical origins remain GitLab. The cross-provider commit check, retrieval URLs and byte fingerprints are recorded explicitly. Provider UTF-8 decoding limits and omitted symlink entries are recorded rather than treated as malware findings.

No upstream installer, agent, exploit, module or container was run. No live malware was detonated and no protected environment was scanned. The collection is not a full dependency, binary, runtime or maliciousness audit.

## Contextual review

- **Detection content:** Sigma, Elastic protection rules, OpenSearch analytics, YARA signatures and Sysmon configurations contain strings for encoded payloads, miners, credential access and Defender tampering. The retained examples are matching conditions or regression data, rather than instructions executed by the source fetcher.
- **ZeekControl:** the encoded-execution match in `ZeekControl/ssh_runner.py` builds a compressed command multiplexer and returns it for the SSH runner. The inspected context shows the encode/compress/decode flow. Remote command orchestration remains an intentional privileged capability, not an execution step in this catalog.
- **Didier Stevens Suite:** `whatisnewtelegramsendmessage.py` sends an explicitly supplied message using a supplied API token and chat ID. It can transmit stdin content when run. The mixed analysis suite is classified for an isolated analysis environment, and message destinations require separate operational review.
- **Mailcow and MISP modules:** the retained Mailcow webhook example is commented and uses placeholder values. The MISP Onyphe expansion constructs a Pastebin reference from enrichment results. These are visible integration/enrichment behaviors; private evidence and API destinations require their own review.
- **RegRipper:** the Defender-related matches in `plugins/defender.pl` and `plugins/ryuk_gpo.pl` read or name registry values for analysis. The quoted matches do not establish that the plugins disable Defender.
- **Qiling and Wireshark CI:** Qiling's inspected workflow changes archive-scanning settings in its CI environment; Wireshark's macOS signing workflow decodes and runs a preparation value supplied through a CI variable. These build-time trust boundaries require separate CI/deployment review. Neither workflow is started by the source fetcher.
- **AppArmor tests:** the retained `spread.yaml` match stops auditd during test preparation. This is a security-control change in test infrastructure, not an action performed when the catalog retrieves source.
- **Maltrail:** the `SECURITY.md` match is a certificate-key fingerprint pipeline ending in `sha256sum`. The broad text heuristic matched the shell-like prefix of the hashing command; the inspected line is not an encoded shell payload execution.
- **Installer and persistence references:** service installation, startup configuration and remote bootstrap examples are expected in endpoint agents, hardening packages and deployment stacks. The source fetcher never runs them. Pattern counts are retained as leads rather than used as an automatic clean/malicious verdict.
- **Explicit holds:** the exact Sleuth Kit and ClamAV commits returned OSV fuzz/advisory records and remain outside active profiles. Trivy retains a conservative hold after the maintainer-documented historical supply-chain incident; no claim is made that its current source pin is malicious. Archived and unresolved projects are held for quality or provenance reasons.
- **Byte handling:** SonarQube's root `start.sh` and `logs.sh` entries were confirmed as Git symlinks and omitted from the regular-file evidence. PingCastle's non-UTF-8 license could not be retrieved byte-faithfully through the provider text interface and was omitted explicitly; inspected source files retain verified Git blob and SHA-256 fingerprints. Neither transport/representation issue is labeled malware.
- **GitLab provenance:** Wireshark, AppArmor and GnuTLS retain their canonical GitLab identities. The exact GitLab commit objects were confirmed in their upstream GitHub mirrors before reading and fingerprinting selected files. The other GitLab candidates without sufficient source access remain outside active downloads.
